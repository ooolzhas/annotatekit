Visual feedback for iOS apps, straight to your coding agent.

Freeze your running app, draw, tap an element or hold on a spot, and say what should change. Hit send: the agent open on your Mac gets the screenshots, exact coordinates and your notes. Nothing to paste, no views to tag, DEBUG builds only.

brew install ooolzhas/tap/annotate
npm install -g annotate-ios
iOS 17+ · SwiftUI and UIKit

How you use it

  1. Tap the Annotate pill. The screen freezes.
  2. Draw around anything, tap to outline an element, or hold half a second to pin an exact spot.
  3. Type what should change. Switch the chip from Fix to Question when you only want an explanation.
  4. Add as many notes as you like, across screens: leave annotate mode, navigate, come back. One send carries them all.
  5. Hit ↑. The agent already open on your Mac picks it up.
  6. The pill narrates the agent's progress; each note's badge spins until it's handled, then turns into a green check.

Works the same in the Simulator and on a physical iPhone, with no extra setup. The whole overlay is behind #if DEBUG, so none of it ships in Release.

What your agent gets

Agents find things by looking, so every note arrives as numbers to check, not a description to interpret.

  • Lightweight screenshots. Saved at 1x: 89% fewer pixels than a regular @3x screenshot and about 3× fewer image tokens, so the agent reads and acts on them faster.
  • Annotated screens and crops. Each screen with numbered blue markers, outlines and your red drawings, plus a native-resolution crop around every pin.
  • Exact coordinates. Each pin's anchor (your tap, or a drawing's center), the element's frame, and its position as percentages across and down, in iOS points from the top-left.
  • Nearby text. The text around each pin, and every visible label on the screen with its frame. Usually enough to grep straight to the right view.
  • Device info. Model, iOS version, screen size and scale, appearance and Dynamic Type size.

Without it, you write "the blue button near the bottom is too small" and the agent guesses. With it, the agent reads Button "Get started" at (24, 300, 120×44), tapped at (84, 322), next to "Light that follows your day".

An excerpt of the agent's prompt:

Agents talk back

Sending isn't the end. The agent reports back to the phone pin by pin as it works.

  • annotation_wait blocks until you send or answer a question, then returns everything: hands-free delivery in any MCP client. The pill's dot is green while an agent listens, yellow while it reconnects, red when nothing listens.
  • Resolve or dismiss. Each pin comes back resolved (with what changed) or dismissed (with why). Tap the note count to see them sorted into Current, In Progress, Resolved and Failed.
  • Ask. When a pin is unclear, the agent asks. The pill flags it, the notes sheet shows a Reply button, and your answer reaches the agent, even from a physical iPhone.
  • Intent. Each note's chip travels into the prompt: Fix changes the code, Question explains it without editing.

Agents report through the MCP tools or the CLI:

annotate resolve <id> <pin> "what changed"
annotate dismiss <id> <pin> "why not"
annotate ask <id> <pin> "question"      # waits for the answer and prints it

Install

Let your agent do it

Tell Claude, Cursor or Codex:

Set up AnnotateKit from github.com/ooolzhas/annotatekit in this app.

The repo's annotate-setup skill guides the agent through any project shape (Xcode project, XcodeGen, Tuist, SwiftPM), the CLI and the connection. In Claude, one plugin brings the skill, MCP server and CLI:

/plugin install annotate --marketplace ooolzhas/annotatekit

Before Claude 2.1.275: /plugin marketplace add ooolzhas/annotatekit, then /plugin install annotate@annotatekit.

By hand

1. The overlay. Add the package with Swift Package Manager and link AnnotateKit to your app target (iOS 17+).

https://github.com/ooolzhas/annotatekit 
import AnnotateKit

@main
struct MyApp: App {
    init() {
        Annotate.install()   // DEBUG-only; a no-op in Release
    }
    var body: some Scene { WindowGroup { ContentView() } }
}

Then add .annotate/ to your .gitignore.

2. The CLI. Not needed with the Claude plugin. Pick one:

brew install ooolzhas/tap/annotate
npm install -g annotate-ios
mint install ooolzhas/annotatekit

Connect your agent

Pick how a send reaches your agent.

Claude + channels Recommended
Sends land in your open session instantly, even while Claude is idle. Start with claude --dangerously-load-development-channels plugin:annotate@annotatekit (or server:annotate without the plugin).
Claude, no flags
Run /annotate-watch; a watcher picks up each send.
Unattended
annotate run in the project root runs claude -p for each send with --permission-mode acceptEdits, resuming the conversation.
Cursor, Codex, VS Code, Claude desktop, any MCP client
Add the MCP server and tell the agent to "keep calling annotation_wait"; each call waits for your next send. Or ask it to "check my latest annotation" when you like.

Channels are a Claude research preview. The development-channels flag skips the allowlist only for the server you name, after you confirm. On Team and Enterprise, an admin must enable channels.

MCP configs for Cursor, VS Code and Codex

The server is annotate mcp (stdio), run from the project root.

// Cursor: .cursor/mcp.json
{ "mcpServers": { "annotate": { "command": "annotate", "args": ["mcp"] } } }

// Nothing installed? npx fetches the CLI on first run (macOS)
{ "mcpServers": { "annotate": { "command": "npx", "args": ["-y", "annotate-ios", "mcp"] } } }

// VS Code: .vscode/mcp.json
{ "servers": { "annotate": { "type": "stdio", "command": "annotate", "args": ["mcp"] } } }
# Codex: ~/.codex/config.toml
[mcp_servers.annotate]
command = "annotate"
args = ["mcp"]

Claude without the plugin: claude mcp add annotate --scope project -- annotate mcp
